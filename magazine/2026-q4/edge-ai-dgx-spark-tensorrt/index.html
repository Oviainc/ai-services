The Cloud, Down to Desk Size: Edge AI on DGX Spark

A capable model running beside the work, on a machine that fits on a desk, changes the privacy, latency and connectivity conversation for agents.

Ovia Inc · Studio and Lab · 5 min read

On October 30, 2026, NVIDIA published a hands-on technical workflow showing developers how to run a serious model on a machine that sits on a desk. The post, titled Run AI Models for Edge Application Development with Just a Few Commands, walks through running Nemotron-3.5 Lightning on DGX Spark, now available in a 64GB configuration, using TensorRT Edge-LLM. A few commands are enough to download the model, build optimised engines for the machine, start a chat session in the terminal, and serve the model through a local, OpenAI-compatible API for application prototyping. The cloud, in other words, has been brought down to desk size, and the desk has become a place where real agent work can begin.

The model at the centre of the workflow is the NVFP4 build of Nemotron-3.5 Lightning, a 30-billion-parameter model with about 3 billion parameters active per token. The first launch downloads about 21GB of model files and builds the TensorRT engines; later runs reuse the cached engines, so the machine settles into a working rhythm after the first setup. That rhythm matters. A prototype that starts quickly, answers locally, and stays on the premises changes how a team thinks about privacy, latency, and cost from the very first experiment.

01 · The announcement

TensorRT Edge-LLM is a lightweight C++ inference runtime designed for embedded workloads, driven through the trtedge command-line interface. The walkthrough uses that interface to download the selected model, build optimised TensorRT engines for the machine, start a chat session in the terminal, and serve the model through a local API. Nothing in the sequence requires a distant fleet. The work happens on the desk, on hardware the developer can see and touch, which makes failures easier to find and fixes easier to test.

The tested setup was specific, and the specificity is part of the value. NVIDIA reports the workflow on TensorRT Edge-LLM 0.11.1 with TensorRT 10.16.1.11, CUDA 13, and Python 3.10 to 3.12, at batch size one, with one concurrent streaming request and a 128-token output limit. Naming the stack and the limits turns a demonstration into something a team can reproduce, vary, and judge honestly on local hardware.

02 · Why it matters

The strategic detail is continuity. NVIDIA designed TensorRT Edge-LLM to carry the same inference framework from development on DGX Spark to deployment on Jetson Thor, DRIVE AGX Thor, and IGX Thor. Prototype and production stop being two different stacks, and the familiar demo-to-field gap, where edge projects quietly die, gets narrower. A team can learn the runtime once, build habits around the runtime, and carry those habits into the field instead of starting again at deployment.

The second detail is locality. A capable model running on premises, beside the work, changes the privacy, latency, and connectivity conversation for agents that handle sensitive data, operate on unreliable networks, or need answers in milliseconds rather than round trips. Local inference also changes the failure picture: a dropped connection to a distant service stops being a total outage, and sensitive material can stay inside the room where the work happens.

03 · The operations and craft angle

The workflow also makes decoding strategy a design decision. NVIDIA reports that enabling DSpark speculative decoding, using three draft tokens in the tested configuration, raised mean generation speed from 73.3 to 108.5 tokens per second on SpeedBench 1K and from 73.4 to 126.9 tokens per second on HumanEval prompts, while median time to first token moved by about two milliseconds or less; peak total system memory during inference was 27.9GB including the operating system. All of those figures are vendor-reported, measured by NVIDIA on NVIDIA hardware.

The craft lesson travels regardless of the exact numbers. Quantisation, engine builds, caching, and decoding choices are operations work, and operations work decides what an agent costs and how the agent feels in use. That is the discipline behind NVIDIA-Certified Professional: AI Operations, and the same pattern runs through the context engineering work at Ovia since December 2022 and the field years at Staywired and Beanfield: infrastructure holds when the kit at the edge matches the plan at the core. A small machine rewards the same care as a large fleet, because the constraints are simply closer to the surface.

04 · Caveats and fine print

Three cautions keep the story honest. First, every performance number in the post comes from NVIDIA testing on NVIDIA hardware and software; independent teams running other models, prompts, and concurrency levels will land in different places, so the figures should be read as vendor-reported until reproduced. Second, real agent workloads with longer outputs and concurrent users will behave differently from a single streaming request with a 128-token limit. Third, a local API on a developer machine is a prototyping step, not a production deployment; authentication, monitoring, updates, and failure handling still have to be built before a desk prototype earns trust in the field.

05 · What to watch

Three signals will show whether the workflow travels beyond the demonstration: whether teams publish independent reproductions of the DSpark gains on real workloads; whether the Spark-to-Thor path becomes the default route for robotics and embedded agents, as the shared runtime promises; and whether the 64GB configuration, offered through manufacturer partners since October 28, puts sustained local-agent development within reach of smaller teams. Each signal is measurable, and each one will show up in published results rather than in launch claims.

The direction is clear either way: serious inference keeps moving closer to where the work happens, and the craft of running models well matters at desk scale just as much as at gigawatt scale.
