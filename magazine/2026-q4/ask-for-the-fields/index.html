Ask for the Fields, Not the Page: A Small Model That Returns Null

A two-billion-parameter model reads a document image and hands back only the named fields, typed, under the keys the receiving system already uses — and leaves an honest blank where the document holds nothing.

Ovia Inc · Studio and Lab · 6 min read

The page was never the product. The fields are. Optical character recognition hands back everything printed on a document, line by line, with no sign of which string is the exam type, which is the date, and which number is the total. For a system waiting on data, completeness is only the halfway point: someone still has to write the code that maps every value to the right field before a database or a scheduler can use any of it.

On November 4, 2026, Dharma-AI published the Field Extractor on Hugging Face, starting exactly where that mapping work used to start. The model takes a document image and returns structured JSON: typed, field by field, nested where the document nests. An invoice comes back with every line item as an ordered list, alongside the totals. An identity document comes back under the names the receiving system already uses. One checkpoint handles contracts, court filings, invoices, identity documents and forms, with no fine-tuning per type.

Key points

  • A two-billion-parameter model from Dharma-AI returns exact fields from a document image as structured JSON, openly or against an exact schema.
  • A field the document does not hold comes back null instead of invented, and a schema-directed answer carries no extra fields.
  • On the maker's own benchmark of 546 documents, the model scored 0.834, ahead of four general-purpose frontier configurations, as reported by Dharma-AI.
  • The craft lesson travels: name the fields first, use the keys the receiving system speaks, and treat an honest blank as data.

01 · The announcement

The Field Extractor offers two ways to ask. In open mode, no schema is supplied: the model reads the page, works out which parts are structured fields, a label followed by a value, a table with a header row over its columns, and returns everything found as key-value pairs. In schema-directed mode, the caller specifies the exact shape wanted, field by field, typed string, number or boolean, under key names the caller's system already uses. Ask for a table and the model fills it row by row, each cell matched to its key. Send a schema and the output follows it exactly, same keys, no extra fields, ready for the next system.

The base is DharmaOCR-LITE v1.1, a new two-billion-parameter version of the maker's document model. On top of that checkpoint, a LoRA adapter was trained on 43,384 field-level examples covering both request modes, drawn from English documents from the public web, real Brazilian documents in Portuguese, and a smaller multilingual share, spanning receipts, invoices, forms and bank statements, as reported by Dharma-AI.

02 · Why it matters

The examples the maker chooses are operational, not decorative. A medical requisition carries a patient name, an exam type and a date, ready to schedule. Supplier invoices land every morning, and four things off each one push into an accounting system. In each case the value sits in a handful of named fields, and so does the cost of an error: a total in the wrong column, a date read as a reference, a blank quietly filled with a plausible invention.

That last failure is the one the design refuses: ask for a field that is not on the document, and the model returns null instead of inventing a value. The benchmark tests that refusal directly. Across 546 documents and 1,638 cases, the three scenarios cover extracting every field with no schema, a partial schema naming only real fields, and a schema that also includes deliberately nonexistent fields. The score is field-level F1, matched by path including position inside a table, weighted by value similarity and valid JSON. On that measure, as reported by Dharma-AI, the small model scored 0.834, ahead of four general-purpose frontier configurations ranging from 0.816 down to 0.741.

Ask for a field the document does not hold, and the answer comes back null instead of invented.

03 · The craft angle: the schema is the context

Context engineering at Ovia since December 2022 treats the request as part of the system, and a schema is a request made precise. Naming the fields before the model runs, typing each one, and fixing the key names to the vocabulary the receiving system speaks removes a whole layer of translation code, and with it a layer of quiet errors. The open mode still earns a place: send an open request when the contents of a document are unknown, and a schema when the output has to match a shape that already exists somewhere else.

The cost argument follows the same discipline. A general-purpose model can do this extraction today with careful prompting. At frontier pricing and latency, on a high-volume task, the general model becomes the expensive way to solve a well-defined problem. The Field Extractor runs self-hosted, priced by the maker at GPU time rather than per token, and reported at six to one hundred forty-seven times lower cost per extraction than the frontier configurations compared. Those are vendor-reported figures, examined below. The structural point stands without them: a bounded, repeated task rewards a small model trained close to that task, on infrastructure the operator controls, over a large general model rented by the call.

04 · Caveats and fine print

The benchmark is the maker's own, and every figure here is reported by Dharma-AI rather than independently replicated. The comparison also prices two different things: frontier figures come from measured token use against published list pricing, with reasoning set to low, while the extractor figure is self-hosted GPU time on one L40S at a rate the maker states, and the maker is candid that the figure is not a sales price. Two public datasets, SROIE and FUNSD, were held out of training, which strengthens the generalization claim: a receipt where every requested field comes back correct, blanks as null, and a form where exactly one checked box of twelve is marked true. The announcement states no licensing terms or commercial offering, so availability beyond the public demonstration remains unconfirmed, and production use still needs validation on the adopter's own document types and languages.

05 · What to watch

The direction matters more than one checkpoint. Document work is where business intelligence meets the physical archive: requisitions in healthcare, invoices in finance, filings in legal and administrative operations. A model class that returns typed fields under the caller's own key names, refuses to invent missing values, and runs on owned infrastructure changes the build decision for those workflows, from renting general intelligence per page to operating a specialized instrument per task.

We watch for the follow-through: stated licensing, independent runs of the benchmark, and quality reported on messy real archives rather than curated sets. Until then, the discipline is already usable on any stack. Name the fields first. Fix the types. Keep the keys the receiving system speaks. And require the answer null when the document holds nothing, because a record is only as trustworthy as the blanks the system was willing to leave blank.
