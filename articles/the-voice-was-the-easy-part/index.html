The Voice Was the Easy Part: Retrieval Decides Whether a Spoken Answer Deserves Trust

A spoken question in Hindi searches an English handbook and hears an answer in Hindi — provided the index understands the question, which is exactly where the first build failed without a sound.

Ovia Inc · Studio and Lab · 6 min read

The voice worked on the first try. The search underneath the voice did not, and the failure made no sound at all.

On November 25, IBM Research published the build on the Hugging Face blog: a farm assistant that listens to a spoken question in Hindi, Tamil, Telugu, Gujarati, Marathi or another Indic language, searches a 154-page agricultural handbook written in English, and answers aloud in two to four sentences in the language of the question. The source pages appear on screen beside the answer, so the answer can be checked. Ask about cricket or coding and the assistant steers the conversation back to farming instead of inventing an answer.

The example the builders lead with is plain field work: how to tell good seed from bad. Nothing in the exchange requires typing, an English screen, or a translated copy of the handbook. One English document serves every language the assistant hears — once the search layer understands more than one language, which is where the build nearly failed in silence.

Key points

  • A spoken question in an Indic language searches a 154-page English handbook and returns a spoken answer in the same language, source pages shown.
  • CUGA, the open-source harness from IBM Research, stays text-in and text-out; speech recognition and synthesis sit in two thin, swappable layers around it.
  • The default embedding model was English-only, so Hindi or Tamil questions retrieved five wrong passages, and the grounded agent answered that the handbook did not cover the question — no error, no warning.
  • The fix: the multilingual embedding model intfloat/multilingual-e5-large, which puts the same meaning in the same place across languages.

01 · The announcement

The harness at the centre is CUGA, the ConfigUrable Generalist Agent from IBM Research, an open-source framework under Apache 2.0 handling model wiring, tools, state and guardrails, so builders write tools and a prompt instead of an agent loop. The voice assistant runs CUGA as an embedded software kit inside a small web application. One setting switches the underlying model between watsonx and OpenAI. A knowledge tool parses the handbook PDF, chunks the text, embeds the chunks and searches them locally. Each question opens a fresh thread, so one person's language and context never leak into another session.

02 · Why it matters

Most useful knowledge sits written and digitised in English. Most of the people who need that knowledge speak and think in other languages, and many would rather talk than type. The gap between the language of the record and the language of the question is not a translation detail; for anyone on the far side of it, the gap is the system. A handbook that cannot be found in the language of the field might as well not exist for the farmer holding a sheaf and a question at the same time.

The pattern reaches past agriculture, as the builders say directly: swap the handbook for scheme documents, health advisories or legal guides and the same architecture answers a different public. Swap the speech provider and the deployment model changes — cloud speech for speed, speech models on local servers where data has to stay home — without rewriting the agent in the middle.

Every layer behaved correctly, and the system still failed — quietly, in the language of the question.

03 · The craft angle: test retrieval in the language of the question

Retrieval works the way retrieval works everywhere: text becomes vectors, and the nearest vectors win. The default embedding model in CUGA reads English only, so a Hindi question becomes a vector carrying almost no meaning. Retrieval still returned five passages for every question. The passages were the wrong ones, and the model — instructed, correctly, to answer only from what retrieval provided — replied that the handbook did not cover the question. No component raised an error, because no component had made one. The fault lived between the components, in the assumption that an English index understands a Hindi question.

The fix was one component: intfloat/multilingual-e5-large, a multilingual embedding model that places the same meaning in the same region of the space whatever the language. Wiring the model into CUGA took a small workaround, documented in the tutorial published with the demo. After the swap, one English handbook serves every language, with no translated copies to make or maintain.

Context engineering at Ovia since December 2022, practised daily across English, French and Spanish, keeps the order of work the IBM Research team recommends at the end of the build report: before tuning a single prompt, ask one question in a non-English language and check that the right pages come back.

Around that check, the small decisions in the build decide whether a spoken answer deserves trust. Answers are written for the ear — no markdown, no bullet points, no citation tags read aloud — and a light formatter strips whatever slips through before speech. Guardrails stay cheap: input checks catch off-topic questions, and a reply beginning with a redirect marker swaps in a polite return to farming, with no second model call slowing the voice path. With cloud speech, the browser talks to the speech service directly and the server receives only text, so keys stay out of the server.

04 · Caveats and fine print

The build is a working demonstration, and the report keeps the claim at that size. No retrieval accuracy figures, recognition error rates, latency numbers or field results with farmers appear in the post, so the honest reading is architectural: the design is inspectable, the demo runs in a browser, and the tutorial rebuilds the assistant layer by layer. An agent told to answer only from retrieved passages is exactly as good as the retrieval in front of the model; when retrieval fails silently, grounding turns the failure into a confident, polite, wrong answer. Teams shipping the pattern need checks on the retrieved pages themselves, not only on the final spoken sentence.

05 · What to watch

Watch the embedding layer become a stated requirement rather than a default. Multilingual products will be judged by whether the index understands the language of the question, and the one-question test is cheap enough to become standard before any prompt work begins. Watch the handbook swap: scheme documents, health advisories and legal guides carry higher stakes than seed selection, and each new corpus tests whether source pages on screen are enough for a listener to trust a spoken answer. And watch where the speech runs. The same harness accepts cloud speech from the browser or open speech models on local infrastructure, which keeps the sovereignty choice open — a choice that decides, in many deployments, whether the service may run at all.

We build voice and language work the way the Studio and the Lab build every engagement: the record stays in one place, the question arrives in the language of the person asking, and retrieval proves itself in that language before anything else is tuned. The voice was the easy part. The finding is the product.
